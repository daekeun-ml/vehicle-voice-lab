# 음성 전처리 설계와 잡음 제거 실험

[원본·DSP·RNNoise 음성 비교](audio-lab.html#noise) · [실험 요약 JSON](../research/audio-front-end/summary.json) · [가이드](README.md)

**제안은 “항상 강하게 잡음을 지우기”가 아니라, 원본을 보존하고 신뢰할 수 있는 잡음만 약하게 줄이는 입력 처리 계층입니다.** 발화 단위 시제품과 RNNoise 비교 실험을 만들었습니다. 앱의 마이크·업로드·Sonic 경로에는 아직 연결하지 않았습니다.

## 현재 앱에 있는 처리

| 위치 | 실제 처리 | 하지 않는 것 |
| --- | --- | --- |
| 브라우저 마이크 | `echoCancellation`, `noiseSuppression`, `autoGainControl` 요청 | 브라우저가 어떤 알고리즘·강도로 처리했는지 앱이 통제하지 않음 |
| 브라우저 발화 구간 | RMS와 적응형 noise floor로 발화 시작·끝 감지 | 주파수 영역 잡음 제거·화자 분리가 아님 |
| PCM → WAV | 16kHz mono 변환 | 별도 Wiener 필터·신경망 잡음 제거 없음 |
| 업로드·시험 WAV | 모델 워커로 전달 | 브라우저의 마이크 잡음 억제를 거치지 않음 |
| Sonic | 브라우저 마이크 처리 후 스트리밍 | 이번 발화 단위 시제품은 적용되지 않음 |

근거: [public/app.js](../public/app.js), [PCM worklet](../public/pcm-worklet.js), [서버](../server.mjs). `getUserMedia` 옵션은 **요청**이며 실제 적용 여부는 브라우저·장치의 설정으로 확인해야 합니다.

## 채택할 구조

1. **입력 이력 기록:** 마이크인지 파일인지, 실제 브라우저 AEC/NS/AGC 설정, 샘플레이트·클리핑·입력 RMS를 기록합니다. 마이크에서 이미 잡음을 억제했다면 서버에서 이중 억제하지 않도록 별도 실험군으로 구분합니다.
2. **원본 유지:** 같은 발화의 원본과 처리본을 보관할 수 있는 평가 경로를 둡니다. 실제 사용자 녹음의 영속 저장은 기본 기능으로 추가하지 않았습니다.
3. **신뢰도에 따른 약한 억제:** 잡음 바닥을 추정할 근거가 없으면 원본을 그대로 통과시킵니다. 정지 구간과 지속성 잡음에 근거가 있을 때만 제한된 감쇠를 적용합니다.
4. **모델별 효과 확인:** 전처리 강도와 STT를 함께 평가합니다. Whisper에 도움이 된 설정이 Qwen3-ASR에도 유리하다고 가정하지 않습니다.
5. **어려운 입력의 재확인:** 원본·처리본의 ASR에서 숫자, 좌석, 부정, 동작이 달라지는 고위험 입력은 임의로 하나를 골라 실행하지 않고 재발화를 요청하는 정책을 검토합니다. 두 전사가 같아도 둘 다 틀릴 수 있으므로 기존 검증기는 유지합니다.

1·4·5는 앱 통합을 위한 설계이며 현재 제품 흐름에 구현된 기능은 아닙니다. 이번에 구현한 것은 2·3의 **오프라인 비교 경로와 잡음 억제 시제품**입니다. 재인식 두 번의 비용·지연도 실제 통합 전에 측정해야 합니다.

## 알고리즘 선택

| 방식 | 검토할 장점 | 이 앱에서 주의할 점 | 이번 상태 |
| --- | --- | --- | --- |
| 고역통과·DC 제거 | 저주파 진동·DC 성분에 간단히 대응 | 중고역 잡음과 동승자 음성을 제거하지 못함 | 필요 시 별도 단계로 검토 |
| 스펙트럼 감산·하드 게이트 | 구현과 원인 분석이 쉬움 | 음악성 잡음, 음절 끝 잘림, 약한 자음 손실 | 강한 게이트는 기본 후보에서 제외 |
| 보수적 적응형 Wiener 계열 | 추가 모델 없이 CPU에서 실행, 감쇠량 제한 가능 | 잡음 추정이 틀리면 말소리도 줄임 | 시제품·A/B 실행 |
| [RNNoise](https://github.com/xiph/rnnoise) | DSP와 신경망을 결합한 실시간 잡음 억제 | 48kHz 경로, 모델 지연, 언어별 인식 영향 | 같은 WAV로 비교 실행 |
| [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet) | 학습 기반 full-band 음성 개선 후보 | 48kHz 경로·실행 환경·추가 지연 검토 필요 | 문서 검토만 수행 |

한 채널의 잡음 제거는 **동승자와 운전자를 구분하는 화자 분리**나 **마이크 배열 빔포밍**의 대체가 아닙니다. 에코 제거도 출력 스피커 참조 신호를 사용하는 별도 문제입니다.

## 구현한 시제품

[runtime/experimental_denoise.py](../runtime/experimental_denoise.py)의 `denoise()` 함수입니다. 기존 기법들을 보수적으로 조합한 실험용 알고리즘이며 새로운 학습 모델을 만든 것은 아닙니다.

| 단계 | 설정·동작 |
| --- | --- |
| 입력 | finite float, 16kHz mono, 최대 30초 |
| 주파수 변환 | 32ms Hann 창, 8ms hop의 STFT |
| 잡음 추정 | 발화 전체에서 낮은 에너지 프레임을 고르고 주파수별 중앙값 사용 |
| 경계 보호 | STFT 패딩으로 생긴 0 구간은 잡음 추정에서 제외 |
| 신뢰도 부족 | 후보 잡음 프레임이 120ms 미만이면 bypass |
| 적응 | 잡음으로 추정한 프레임에서만 PSD를 천천히 갱신 |
| 필터 | decision-directed 사전 SNR 기반 Wiener gain, 주파수·시간 평활화 |
| 최대 감쇠 | 주파수별 gain을 -9dB 아래로 내리지 않음 |
| 자음·시작 보호 | 3kHz 이상 gain 최소 0.55, 급격한 발화 시작은 최소 0.85 |
| 끝 음절 보호 | 억제는 천천히 증가시키고 신호 복원은 빠르게 |
| 원본 혼합 | 원본 15% + 처리본 85%, 자동 음량 정규화 없음 |
| 출력 | 입력과 동일한 길이·샘플레이트, 새 클리핑 방지 |

**발화 전체를 본 후 잡음을 추정하므로 스트리밍 필터가 아닙니다.** 현재 발화 단위 cascade/audio-control 경로의 후보이며, Sonic에 넣으려면 지연·과거 프레임만 사용하는 추정·상태 유지 정책을 따로 설계해야 합니다. 낮은 에너지 프레임은 휴리스틱이며 실제 무음/VAD 정답이 아닙니다.

## 실제로 돌려 본 결과

기존 합성 음원 **2개**에 인공 잡음 **2종 × SNR 20/10/0dB**를 넣은 12조건과 깨끗한 대조군 2개를 사용했습니다. 잡음은 저역에 치우친 색 잡음·100/200Hz 톤, 여기에 짧은 burst를 더한 경우입니다. 실제 주행 녹음이 아닙니다. 앞뒤에 0.4/0.5초의 정지 구간을 넣은 제한된 시험입니다.

| 후보 | 신호 SNR 변화¹ | 원본 대비 ASR 정답 대용 일치도 개선 / 동일 / 악화² |
| --- | --- | --- |
| 보수적 DSP | 필터가 작동한 10조건에서 약 +0.8~+4.1dB; 2조건 bypass | **1 / 10 / 1** |
| RNNoise | 12조건에서 약 -0.6~+11.2dB | **1 / 8 / 3** |

¹ 깨끗한 기준 음원을 사용한 파형 오차 기준입니다. RNNoise는 깨끗한 대조군에서 측정한 **고정 20ms 지연**을 보정한 뒤 비교했고, 각 잡음 사례마다 유리한 지연을 다시 찾지는 않았습니다. live 경로에서는 이 지연이 없어지는 것이 아닙니다.

² `Whisper large-v3-turbo`가 깨끗한 원본에서 얻은 전사를 **정답 대용**으로 삼았습니다. 사람이 검수한 전사 정답에 대한 CER가 아니며, 정답 대용 자체에도 “김서림 → 김사림” 오류가 있습니다. 같은 오차율이어도 실제 단어는 다를 수 있습니다.

사례:

- 색 잡음 10dB의 김서림 안내에서 DSP는 “앞머리”를 원본 대조군의 “앞유리”로 되돌렸습니다.
- 같은 음원의 0dB에서는 DSP가 신호 SNR을 개선했지만 ASR 일치도는 나빠졌습니다.
- 조수석 명령의 0dB에서 RNNoise는 신호 잡음을 크게 줄였지만 ASR이 “조수석”을 “중수석”으로 바꿨습니다.

따라서 **SNR·청감 개선만으로 차량 명령용 전처리를 선택하면 안 됩니다.** 이 소규모 결과로 RNNoise나 DSP를 앱 기본값으로 켜지 않았습니다. 고난도 문장·여러 사람의 자연 발화·실제 차량 소음으로 숫자·좌석·부정 오류와 최종 제어 결과를 추가 검증해야 합니다.

DSP의 로컬 처리 시간 중앙값은 약 19ms, RNNoise 비교 파이프라인은 약 322ms였습니다. 전체 파일 처리와 Python 래퍼·리샘플링을 포함한 이 호스트의 참고값이며, 실시간 프레임 지연이나 차량 장비 성능이 아닙니다. ASR은 **RTX PRO 4500 Blackwell Server Edition**에서 실행했으며 가이드의 L40S 배포 서버 실측으로 표시하지 않습니다.

## 재현

필요한 Python 패키지와 측정 버전은 [신호 결과](../research/audio-front-end/signal-metrics.json), [RNNoise 결과](../research/audio-front-end/rnnoise-metrics.json), [ASR 결과](../research/audio-front-end/asr-diagnostic.json)에 기록했습니다. Python 환경에 NumPy·SciPy·SoundFile, 비교용 pyrnnoise, ASR용 PyTorch·Transformers를 설치한 뒤:

```bash
python tests/test_experimental_denoise.py
python scripts/noise-reduction-probe.py
python scripts/rnnoise-probe.py
# 먼저 Kokoro 시험도 생성한 경우 두 시험의 ASR 진단을 함께 수행
python scripts/audio-probe-asr.py
python scripts/render-audio-probes.py
```

4개 단위 테스트로 무음·짧은 입력·일정 에너지 입력의 bypass, 잘못된 입력 거부, 시작부터 음성이 있는 경우, 길이·유한값·원본 불변·재현성을 확인했습니다. 이 테스트의 통과는 인식 품질의 통과를 뜻하지 않습니다.
