# STT 4종 비교와 실습

Qwen3-ASR 0.6B·1.7B를 GPU2에 연결했습니다. Whisper와 Nemotron은 GPU1에서, Qwen3-ASR 두 모델은 GPU2에서 실행합니다. 모두 서울 리전의 동일한 g6e.2xlarge / NVIDIA L40S 사양입니다.

## 웹에서 직접 비교

1. [STT 비교 화면](https://d2ub6bbyf1c3sv.cloudfront.net/#asr-lab)을 엽니다.
2. 30초 이하 음성 파일 하나를 선택하고 **4개 STT 비교**를 누릅니다.
3. 브라우저가 한 번만 16kHz 모노 WAV로 변환한 동일 입력을 네 모델에 보냅니다.
4. 인식문, 모델 이름, 인식 시간, 모델 로드 시간, 전체 요청 시간을 비교합니다. 이 시험은 차량 설정이나 대화 기록을 변경하지 않습니다.
5. **차량 대화에 사용**을 누르면 해당 STT가 선택됩니다. 차량 대화의 **모델·음성 설정 → 음성 인식**에서도 직접 선택할 수 있습니다.

Qwen3-ASR은 한국어를 명시하고 BF16/Transformers/SDPA로 실행합니다. 현재 GPU2의 Qwen3-ASR 0.6B·1.7B는 각각 독립 프로세스로 상주합니다. Step·MiMo·Qwen3-Omni의 교체 잠금과 분리돼 있어, 제어 벤치마크가 실행 중이어도 STT를 호출할 수 있습니다. 같은 STT의 요청은 모델별 최대 4개 대기열에서 순서대로 처리합니다. 대기열이 가득 차면 503으로 알리며 다른 STT로 대체하지 않습니다.

| 선택 ID | 정확한 모델 | 고정 revision |
|---|---|---|
| whisper | openai/whisper-large-v3-turbo | 41f01f3fe87f28c78e2fbf8b568835947dd65ed9 |
| nemotron | nvidia/nemotron-3.5-asr-streaming-0.6b | 기존 core worker의 설치 버전; 이번 비교에서 별도 revision 고정 없음 |
| qwen3-asr-06b | Qwen/Qwen3-ASR-0.6B | 5eb144179a02acc5e5ba31e748d22b0cf3e303b0 |
| qwen3-asr-17b | Qwen/Qwen3-ASR-1.7B | 7278e1e70fe206f11671096ffdd38061171dd6e5 |

## 고정 벤치마크

총 **206개 입력 × 4개 STT = 824건**입니다. 결과는 [웹 표](https://d2ub6bbyf1c3sv.cloudfront.net/#asr-lab)와 [요약 JSON](https://d2ub6bbyf1c3sv.cloudfront.net/api/asr/evaluation)에 표시합니다.

| 조건 | STT별 입력 수 | 목적 |
|---|---:|---|
| 기존 31개 + 고난도 48개 원음 | 79 | 동일 문장에 대한 인식 비교 |
| 동일 79개 + 노이즈 제거 | 79 | 전처리로 깨끗한 음성이 손상되는지 확인 |
| 유색 잡음 10dB, 전처리 전/후 | 12 × 2 | 저주파 중심 합성 잡음 |
| 백색 잡음 0dB, 전처리 전/후 | 12 × 2 | 강한 광대역 합성 잡음 |

잡음 부분집합은 STT 결과를 보기 전에 각 원본 세트의 앞 6개로 고정했습니다. 원래 31개 중 3개는 이미 백색 잡음 20dB가 적용된 입력입니다. 따라서 표의 ‘원음’은 입력 세트를 변경하지 않았다는 뜻이며, 전부 무잡음이라는 뜻이 아닙니다. 합성 잡음은 실제 도로·차량 실내 녹음의 대체물이 아닙니다.

전처리는 `conservative-dd-wiener-v1`을 그대로 사용합니다. 발화 전체의 조용한 프레임에서 잡음을 추정하고, 주파수별 감쇠와 시간 평활화를 적용합니다. 최대 감쇠 9dB, 고주파 자음 보호, 원음 15% 혼합을 사용합니다. 신뢰할 조용한 구간이 없으면 원음을 통과시킵니다. 음성 인식 정답을 이용해 필터를 조정하지 않습니다. 웹 직접 비교는 원음 경로이며, 전처리 A/B는 고정 벤치마크에서 수행합니다.

이번 입력에서는 원음 79개와 유색 잡음 12개에 필터가 적용됐고, **백색 잡음 0dB의 12개는 모두 ‘신뢰할 조용한 프레임 없음’으로 우회**했습니다. 필터 감쇠는 적용되지 않았습니다. 다만 float64→float32→PCM16 저장 경로 때문에 각 파일의 2~21개 샘플에서 최대 1 LSB 차이가 있어 비트 단위 동일 파일은 아닙니다. 이 조건의 작은 점수 차이를 노이즈 제거 효과로 해석하면 안 됩니다. 강한 잡음에서 현재 추정기의 한계로 기록합니다.

### 점수를 읽는 방법

- **CER**: 공백·문장부호를 제거한 한국어 문자 편집 거리 / 정답 문자 수. 숫자 `24`와 `이십사`의 표기 차이는 유지합니다. 의미가 같아도 표기 차이로 오류가 늘 수 있으므로 CER만으로 결론내리지 않습니다.
- **숫자·좌석·목적지**: 정답에 있는 명시적 언급의 순서와 값이 일치하는지 봅니다. 숫자는 기존 숫자 표기 정리와 일부 고유어 수사를 정리합니다. 음수 부호와 모든 고유어 수사를 완전히 다루는 지표는 아닙니다. 좌석은 운전석/조수석/양쪽, 목적지는 서울역/서울숲에 한정한 보조 지표입니다. 일반적인 개체명 인식 점수가 아닙니다.
- **인식 시간**: 워커에서 한 건을 처리한 시간의 중앙값. 모델 초기 로드와 네트워크 왕복은 제외합니다. RTF는 이 시간을 음성 길이로 나눈 값입니다.
- **제어 동작·상태**: 인식문을 같은 **Qwen3.5 4B BF16 / compact-v2 / deterministic**에 넣고 실제 앱의 동작과 최종 상태를 정답과 비교합니다. 답변 의미나 TTS 청취 품질 점수는 포함하지 않습니다.

고난도 48개는 고정된 이전 차량 상태·대화 문맥을 매 입력마다 주입합니다. 기존 31개의 후속 명령은 동일 정답 텍스트로 선행 명령을 실행합니다. 이 방식은 이전 발화의 STT 오류가 다음 발화에 누적되지 않도록 STT 한 건의 영향을 분리합니다.

원본 파형, 필터 설정, 해시, 인식문, 모델 버전, 오류, 최종 동작은 결과 파일에 보존합니다. 824건은 GPU2의 순차 모델 교체 구성에서 측정한 기록입니다. 이후 웹 STT의 429 충돌을 해결하기 위해 ASR 워커를 분리했습니다. 따라서 표의 지연은 측정 당시 구성의 값이며, 독립 ASR과 다른 모델의 동시 요청 지연은 별도 검증입니다. 워커는 웹 데모와 공유하므로 독점 GPU 성능 측정은 아닙니다. STT 비교 동안 MiniCPM은 GPU1 메모리 확보를 위해 일시 중지하며 완료 후 복구합니다.

제어 실패에는 STT 오류와 고정 제어 모델의 추론 오류가 모두 포함됩니다. 제어 모델을 고정했다는 이유만으로 모든 실패를 STT 탓으로 해석하면 안 됩니다. 모델별 원시 결과는 `/api/asr/evaluation/whisper`, `/api/asr/evaluation/nemotron`, `/api/asr/evaluation/qwen3-asr-06b`, `/api/asr/evaluation/qwen3-asr-17b`에서 확인합니다.

GPU2의 `/opt/vehicle-speech`에 `runtime/qwen_asr_worker.py`, `runtime/speech_manager.py`, `runtime/bootstrap_asr.sh`, `runtime/bootstrap_asr_services.sh`를 배치하고 `bash bootstrap_asr.sh`를 실행합니다. 라이브러리 환경은 `asr-requirements.lock`에 저장됩니다.

```bash
python scripts/build-asr-comparison.py
ASR_BENCH_BASE=http://127.0.0.1:8789 node scripts/run-asr-comparison.mjs
```
